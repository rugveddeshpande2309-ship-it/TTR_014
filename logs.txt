2nd prompt to antigravity 

Build a complete, working website called "Daybloom", a student goal tracker and daily habit dashboard.

TECH RULES
- Use plain HTML, CSS and JavaScript only. No frameworks, no build tools, no external libraries, no CDN links, no API calls.
- Files: index.html, style.css, script.js (all in one folder, opens by double-clicking index.html).
- Save ALL data in browser localStorage so goals, progress, points, profile and theme survive a refresh.
- Wrap every localStorage read/write in try/catch and handle empty or corrupted data without crashing.
- Do not invent features, libraries or data beyond what is listed here. If something is unclear, choose the simplest option and add a short code comment explaining it.
- EVERY button and link on the screen must do something real. No dead or placeholder buttons.

PROBLEM STATEMENT
Many students find it hard to stay consistent with studying, exercising, reading and other personal goals. It is easy to forget what you planned for today, and hard to tell whether you are actually improving. The site should feel like a simple, friendly dashboard for your day.

PAGES / SECTIONS (single page app with a top navigation bar that switches sections without reloading)
1. Dashboard (home)
   - App name "Daybloom" and navigation: Dashboard, Goals, Progress, Profile.
   - Today's date (full format, e.g. "Friday, 16 October 2026"), generated from the system date.
   - Greeting using the student's name if saved (e.g. "Hello, Riya!"), otherwise "Hello there!".
   - Quick summary cards: total goals, goals done today, completion percentage today, current points.
   - Reminder panel: lists today's pending (not yet done) goals. If none are pending and goals exist, show a "All done today!" message. If no goals exist, show a friendly prompt with a button that goes to the Goals section.
   - Motivating quotes banner: a rotating motivational line that changes automatically every 6 seconds with a smooth fade. Use a built-in array of at least 15 short original motivational lines. Also show a new random motivating message in a toast (a small popup) every time a goal is marked done, and once on every page load.
   - At the very bottom of the main page, show the tagline: "Small goals, done daily, grow into big wins."

2. Goals
   - Show each goal as a card with: name, category, a done/not done toggle button, an Edit button and a Delete button.
   - "Add Goal" form with a name (required, trimmed, max 60 characters) and a category dropdown: Study, Exercise, Reading, Health, Hobby, Other. Block empty names and show a clear error message.
   - Edit: opens a modal or inline form pre-filled with the current values and saves changes.
   - Delete: asks for confirmation before deleting.
   - Goals are DAILY and repeat every day. Completion is stored per date so each day has its own tick state.
   - Optional category filter buttons above the cards (All + each category) that actually filter the list.

3. Progress
   - Today's completion percentage with a visual progress bar or ring.
   - Weekly view: a simple bar chart of the last 7 days showing completion percentage per day, built with plain HTML/CSS or inline SVG (no chart library). Label each bar with the weekday.
   - Streak counter: number of consecutive days (ending today, or ending yesterday if today is not finished yet) on which ALL goals existing that day were completed. A day with zero goals does not count toward the streak. Also show the best streak ever.
   - Points total and a small history list of the last 10 point changes (e.g. "+10 Completed: Read 10 pages", "-5 Missed: Gym").

4. Profile
   - Form to save: Name, Age (number, valid range 10 to 100), Standard/Class (text or dropdown, e.g. "1st Year", "12th", "11th", etc.).
   - Save and Clear Profile buttons, both working.
   - A toggle button labelled "College Student". The reference books section appears ONLY when this button is turned ON (and is saved in localStorage). When OFF, the section is completely hidden.
   - When ON, show a "Reference Books for 1st Year College Students" section listing EXACTLY these books and no others:
       * Higher Engineering Mathematics, B.S. Grewal
       * Advanced Engineering Mathematics, Erwin Kreyszig
       * Let Us C, Yashavant Kanetkar
       * The C Programming Language, Brian W. Kernighan and Dennis M. Ritchie
       * Engineering Physics, Gaur and Gupta
       * Engineering Chemistry, Jain and Jain
       * Engineering Drawing, N.D. Bhatt
       * A Foundation Course in Human Values and Professional Ethics, R.R. Gaur, R. Sangal, G.P. Bagaria
   - Show each as a small card with the title, author and a one-line note on the subject it helps with. Do NOT add links, prices, ISBNs or edition numbers.

REWARD POINTS SYSTEM (implement exactly like this)
- Marking a goal done: +10 points.
- Un-marking a goal done on the same day: -10 points (reverses the reward, so points cannot be farmed by toggling).
- At each new day, for every goal that existed on a past day and was NOT completed, deduct 5 points once. Keep a "lastProcessedDate" in localStorage so penalties are never applied twice. Only process dates after the last processed date, up to yesterday, and only for goals that already existed on those dates (store the goal's createdDate).
- Points never go below 0.
- Show a toast for every point change (e.g. "+10 points! Nice work" or "-5 points for yesterday's missed goal").
- Also show a simple level label based on points: 0-49 Seedling, 50-149 Sprout, 150-299 Bloom, 300+ Full Bloom.

LIGHT / DARK MODE
- A visible toggle button in the navigation bar switches between light and dark mode.
- Save the choice in localStorage. On first visit, follow the system preference (prefers-color-scheme).
- Use CSS variables for all colors so both themes look polished with good text contrast.

DESIGN
- Aesthetic, friendly and calm: soft pastel gradient accents (fresh green / teal / lavender), rounded cards, soft shadows, a clean Google-free system font stack, smooth hover and transition effects, and a small flower or sprout emoji or inline SVG as the logo.
- Fully responsive for phone (360px and up), tablet and laptop using CSS Grid/Flexbox and media queries. On phones, the navigation becomes a bottom bar or a hamburger menu that actually works. No horizontal scrolling at any width. Touch targets at least 44px.
- Accessible: semantic HTML, labels on all inputs, visible focus states, aria-labels on icon-only buttons.

DATA MODEL (localStorage, one key "daybloom_data", JSON)
- profile: { name, age, standard, collegeStudent }
- goals: [ { id, name, category, createdDate } ]
- completions: { "YYYY-MM-DD": [goalId, goalId, ...] }
- points: number, pointsLog: [ { date, change, reason } ]
- lastProcessedDate, bestStreak, theme
Use the LOCAL date (not UTC) to build the YYYY-MM-DD strings so the day changes at local midnight. Generate goal ids with Date.now() plus a random suffix.

EDGE CASES TO HANDLE
- Deleting a goal removes it from future calculations and completions, without breaking past percentages unrelated to it.
- Division by zero when there are no goals (show 0%, never NaN).
- Very long goal names must wrap inside the card.
- Escape user text before inserting it into the page (use textContent, not innerHTML) to prevent HTML injection.
- Refreshing the page must restore everything exactly.

QUALITY CHECK BEFORE FINISHING
1. Test adding, editing, deleting and ticking goals, then refresh and confirm everything persists.
2. Confirm points go up and down exactly as specified.
3. Confirm the streak and the 7-day chart update correctly.
4. Confirm the College Student toggle shows and hides the book list.
5. Confirm light/dark toggle persists.
6. Confirm there are no console errors and every button works.
7. Check the layout at 360px, 768px and 1280px widths.
Then give me a short summary of the files created and how to run them.
